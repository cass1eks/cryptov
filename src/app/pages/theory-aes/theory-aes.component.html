1. Что такое AES — простыми словами

AES (Advanced Encryption Standard) — это симметричный блочный алгоритм шифрования. Это значит, что:

  • Симметричный — один и тот же ключ для шифрования и расшифровки
  • Блочный — данные разбиваются на блоки по 128 бит (16 байт)

Если сообщение короче — его дополняют (padding). Если длиннее — разбивают на блоки.

💡
Интересный факт: оригинальное название алгоритма — Rijndael, по фамилиям бельгийских криптографов Joan Daemen и Vincent Rijmen. NIST немного адаптировал его и получил AES.

2. Как работает AES — наглядно

📦

Шаг 1: Подготовка данных

Текст "hello" (5 байт) добивается до 16 байт с помощью padding:

6865 6C6C 6F 0B0B 0B0B 0B0B 0B0B 0B0B 0B0B

🟢 Байты текста ⬜ Padding (заглушки)

🔄

Шаг 2: 10 раундов перемешивания

Данные проходят через 10 раундов, каждый состоит из 4 операций:

🔄

SubBytes

Замена каждого байта по секретной таблице (S-Box)

68 → 4565 → 4D6C → 50
→
↔️

ShiftRows

Сдвиг строк: 1-я без сдвига, 2-я на 1, 3-я на 2, 4-я на 3

Строка 2: [65,0B,0B,0B] → [0B,0B,0B,65]
→
✖️

MixColumns

Перемешивание каждого столбца — один байт влияет на весь столбец

A' = 2·A ⊕ 3·B ⊕ C ⊕ D
→
🔑

AddRoundKey

XOR с раундовым ключом — единственный шаг, зависящий от пароля

Data ⊕ Key = Result

💡 9 раундов — полные, 10-й — без MixColumns

🎯

Шаг 3: Результат

После 10 раундов данные полностью неузнаваемы:

hello → x7!qR#2mK9$pL@5w

🃏 Аналогия с колодой карт

Представь, что ты перемешиваешь колоду карт:

🔄SubBytes

Замена каждой карты по таблице

↔️ShiftRows

Сдвиг рядов карт

✖️MixColumns

Тасовка столбцов

🔑AddRoundKey

Добавление карт из секретной колоды

После 10 перемешиваний никто не узнает исходный порядок карт!

3. Путешествие одного байта

Проследим, как меняется байт 'h' (68) на каждом раунде:

Исходный: 68 'h' в открытом тексте
Раунд 0: 68→60 AddRoundKey
Раунд 1: 60→D0→A2→89 SubBytes → MixCol → AddKey
Раунд 10: XX→69 Финальный результат!

4. Зачем нужен каждый шаг?

🔄 Зачем нужен SubBytes? {{ faqOpen === 1 ? '−' : '+' }}

SubBytes создаёт нелинейность. Без неё шифр был бы уязвим для линейного криптоанализа — можно было бы решить систему уравнений и найти ключ.

↔️ Зачем нужен ShiftRows? {{ faqOpen === 2 ? '−' : '+' }}

ShiftRows перемешивает байты между столбцами. Это создаёт диффузию — каждый байт влияет на соседние столбцы в следующем раунде.

✖️ Зачем нужен MixColumns? {{ faqOpen === 3 ? '−' : '+' }}

MixColumns распространяет влияние одного байта на весь столбец. Изменение одного бита во входных данных меняет весь блок — это лавинный эффект. Последний раунд без MixColumns для обратимости.

🔑 Зачем нужен AddRoundKey? {{ faqOpen === 4 ? '−' : '+' }}

Это единственный шаг, зависящий от ключа. Все остальные операции — открытый алгоритм. Без ключа расшифровать данные невозможно.

🔢 Почему именно 10 раундов? {{ faqOpen === 5 ? '−' : '+' }}

Уже после 4-5 раундов достигается полное перемешивание. 10 раундов дают запас прочности против будущих атак. AES-192 (12 раундов) и AES-256 (14 раундов) — ещё надёжнее.

5. AES vs другие алгоритмы

🔷 AES

"Сложный сейф"

  • 10-14 проверок (раундов)
  • Ключ 128-256 бит
  • Блок 128 бит
  • Современный стандарт
🔶 DES

"Старый замок"

  • 16 проверок (раундов)
  • Ключ всего 56 бит
  • Блок 64 бит
  • Устарел, взломан
💚 Кузнечик

"Российский сейф"

  • 10 проверок (раундов)
  • Ключ 256 бит
  • Блок 128 бит
  • ГОСТ стандарт

7. Режимы работы

ECB (Electronic Codebook) — никогда не используйте

Каждый блок шифруется независимо. Одинаковые блоки → одинаковый шифротекст.

⚠️ Уязвимость: если зашифровать изображение в ECB, силуэты объектов останутся видны.

CBC (Cipher Block Chaining) — стандарт де-факто

Каждый блок XOR-ится с предыдущим шифротекстом. Нужен IV.

GCM (Galois/Counter Mode) — современный стандарт

Сочетает шифрование с аутентификацией. Проверяет, не был ли шифротекст изменён.
